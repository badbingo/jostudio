§1 SCOPE AND INTEGRITY
══════════════════════════════════════════════════════════════════════════════

1.1 性质
  本轮为 Frozen V3 Historical Event Correspondence Review：
  把 Owen 与 Jassica 已登记的重大真实事件，与 Frozen V3 已产生的
  raw output（annual snapshot / month probe / exact-day probe /
  R-1/R-2/R-3/R-4/R-6）逐事件并置，描述两者在哪里对应、在哪里不对应、
  哪里因数据缺口无法判断。

1.2 边界确认（逐项）
  - V3 source / test / BacktestData / event registry / H1 protocol /
    Phase A–C 规则 / N1 / N2 / thresholds / calibration / DomainMapper /
    V3Core / Snapshot / State / Adapter / UI ：零修改。
  - 不根据历史事件反向调整算法；不提出新算法规则；
    不修改 domain / severity / cutpoint / magnitude / focus / watch / mainLine。
  - 不运行任何 V3 / 不补 probe / 不重跑。全部 raw 为既有冻结文件只读转录。
  - 不 commit / 不 push。
  - 历史事实只作为 comparison target，不作为算法设计输入。

1.3 认知暴露披露（强制原文）
  Event-domain registration was previously exposed to assistant influence;
  therefore this review is descriptive/forensic and is NOT claimed to be a
  fully blinded H1 validation.
  本轮不执行 H1 Phase A（不执行任何 PI、不创建 v1.2 / transcript、
  不重新登记、不重新询问任何事件、不要求 blind classification）。
  该暴露不妨碍对已冻结事件事实与 Frozen V3 raw output 的逐事件描述性比较。

1.4 对应性四档词汇（本轮统一用语）
  CLEAR CORRESPONDENCE      ：V3 已有输出与实际事件在事件语义、时间窗口
                              和/或 domain signal 上存在明显对应。
  PARTIAL CORRESPONDENCE    ：存在相关信号，但时间、domain、方向或粒度
                              只有部分对应。
  NO CLEAR CORRESPONDENCE   ：已有 raw evidence 中没有明显与该事件对应的
                              V3 signal。
  INDETERMINATE             ：因日期精度不足、所需 annual snapshot 不存在、
                              月/日未 probe、事件语义不足以判断或其他明确
                              数据缺口，目前不能判断。
  辅助用语：evidence present / evidence absent / evidence insufficient。

1.5 与 V2 报告五档词汇的映射（登记，不改写 V2 原文）
  V2「clear structural」→ CLEAR；V2「partial」→ PARTIAL；
  V2「weak」→ PARTIAL(weak)；V2「no clear correspondence」→ NO CLEAR；
  V2「insufficient / not assessable」→ INDETERMINATE。
  凡 V2 已有分级的事件，本轮在引用时保留其原始分级词并给出映射。

1.6 日期精度规则（沿用 H1 §5/§6，零放宽）
  - EXACT_DATE：年/月/日三层各自独立登记，互不替代。
  - MONTH_ONLY：只做月粒度比较；月锚点（15 日）不当作事件真实日期；
    禁止虚构具体日期。
  - YEAR_ONLY：只做年层比较；一侧既有 day probe raw（S9/P02、
    S10/P01-SALE、S11/P03A+P03B、S12/P04）仅登记为证据覆盖事实，
    不作为年层对应证据。
  - Calendar Year vs Resolved V3 Year 分离登记：
    S5  2009-02-03 → resolvedV3Year = 2008（立春前）
    S8  2017-01（Owen 侧 2016-08）→ 双侧 resolvedV3Year = 2016
    S10 2021-02-01 → resolvedV3Year = 2020
    禁止用 calendar-year snapshot 顶替 resolved-year snapshot。

1.7 语义规则（本轮强制）
  - Property 语义规则：买房 / 买办公楼 / 房产交易 ≠ Owen business success、
    ≠ profit、≠ personal wealth increase（大部分房产购买主要来自
    Jassica 收入）。V3 wealth signal 与 property event 之间最多只能说
    「语义上存在一定关联」，不得写「正确对应财富增加」。
  - J2 语义规则：「公司收入创新高」= revenue record。income ≠ profit、
    income ≠ wealth increase、income ≠ career success。事件名保持注册表原样。
  - E6 事实基线（Owner 修正后，本轮唯一采用版本）：
    P1 2006 项目启动、大额投入；P2 2007 严重技术问题、延误；
    P3 2008 持续延误、时间与资金压力增加；
    P4 2009 项目进入 launch / operations transition（不是最终失败）；
    P5 2009–约2012 公司继续运营、项目继续产生大量成本；
    P6 约2012 开始准备停止项目；
    Outcome 约2012+ 最终结束，累计总投入超过 $3M，总体严重亏损。
    禁止表述「2009 年项目最终失败 / 2009 年巨亏结束」。
    [PROVENANCE NOTE] V2 报告 §7.2 表 P4 行标签为「上线失败损失>$3M」，
    系修正前事实表述。本轮按修正后事实解释 E6；该措辞差异不影响

    P4 的对应性结论在两种读数下不变（NO CLEAR）。

1.8 每事件输出结构
  A. Real-world event（ID / 事实 / calendar 日期 / 精度 / resolved year）

§12 WHAT WE SHOULD NOT CONCLUDE YET
══════════════════════════════════════════════════════════════════════════════

  1. 不能从这批案例计算 V3 accuracy / hit-rate / precision / recall——
     样本非随机、事件非独立、精度不一、domain registration 受暴露影响，
     且本轮四档判定为描述性而非预注册判据下的判定。
  2. 不能证明 V3 已经经过统计验证；也不能证明 V3 不准确。
  3. 不能因为一个人的一个事件（如 E5 2000）就修改算法。
  4. 不能根据这些案例重新 calibration / threshold / cutpoint /
     magnitude / severity / domain mapping。
  5. 不能把 property event 自动解释为 wealth success 或 wealth
     increase（大部分房产购买主要来自 Jassica 收入）。
  6. 不能把 J2 的 revenue record 自动解释为 profit 或个人财富增加。
  7. 不能把 E6 的 2009 年（P4）写成「项目最终失败 / 巨亏结束」——
     修正后事实为 launch / operations transition；最终结束在约 2012+。
  8. 不能把 date resolution 问题当成 algorithm mismatch
     （S5→2008、S8→2016、S10→2020 均为解析规则的正确执行）。
  9. 不能把「年层 quiet + 事件存在」直接当作算法错误——必须先检查
     snapshot 存在性、日期精度、domain 对应、月/日层信号、以及
     「架构是否本来不保证每个现实事件进入 annual focus」（本轮多个
     NO CLEAR 案例即属此类，且 S5/Owen 证明年层 quiet 时 day 层仍可
