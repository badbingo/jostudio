§0 EXECUTIVE SUMMARY
================================================================================

本轮是 V4 Event Semantics Architecture 的第二轮 Architecture Hardening。
架构方向不变：V3 = Structural Authority（冻结）；V4 = Event Semantics
Authority；AI = Explanation Layer。Model C 分层证据管线保留。本轮把 v1
设计中发现的 10 个架构硬问题（H1-H10）收紧为可冻结的 contract 条款。

十项 hardening 决议（详细条款见对应章节）：
  HD-1 (H1)  正式建立 Layer A Structural Fact / Layer B Semantic Evidence /
             Layer C Event Candidate 三层，配 Supplementary Evidence
             Boundary 四桶与 Second-Engine Test（§3、§8）。
  HD-2 (H2)  **废除 v1 §9.4 的 EXACT_DATE 定义**。Day same-family evidence
             = corroboration only，永不单独升级 timing；EXACT_DATE 需四条件
             合取（§10）；Timing Evidence 与 Event Identity Evidence 分离
             （§9）。本版 registry 未登记任何 class-specific discriminator
             → **EXACT_DATE 在 v1 contract 内不可达（reserved state）**。
  HD-3 (H3)  Level-1 Family 词表收窄为 9 个语义宽家族 + 1 个跨家族聚合视图；
             修正 v1 taxonomy 的 3 处 L1 命名泄漏（§4）。
  HD-4 (H4)  废除 v1 单一 ConfidenceOrdinal（insufficient/single-signal/
             corroborated/broad/conflicted），改为三个独立正交字段：
             EvidenceStatus × EvidenceBreadth × Corroboration；禁止跨维
             单一 ordinal ladder；零 Double（§11）。
  HD-5 (H5)  School Plugin 权限收紧：coreEvidenceState 与 pluginEvidenceState
             分离；plugin 八项禁令；plugin 抬升 insufficient→supported 必须
             显式登记；Snapshot 必须能回答「关闭全部 plugin 候选是否仍存在」
             （§15）。
  HD-6 (H6)  AmbiguityClass C = HARD CEILING：C + L3 = INVALID（§14）。
             v1 Matrix 中 Immigration（L2-L3）等违例已修正（§18）。
  HD-7 (H7)  Property / Finance / Business 语义：structural domain signal
             ≠ event identity；无专属 detector 的 class 只能经显式登记的
             semantic conjunction 形成（§5.4、§18）。
  HD-8 (H8)  Temporal 冻结：Year=broad / Month=timing-window / Day=narrow
             corroboration；三条 backflow 禁令；Temporal Resolver 只回答
             「evidence observed at what temporal resolution」（§9）。
  HD-9 (H9)  OQ-2 = CLOSED / YES（R-6 消费 + provenance 契约）；OQ-3 =
             CLOSED / NO；OQ-1 / OQ-4 / OQ-5 = DEFERRED（附保守 interim
             规则，§21）。
  HD-10 (H10) EventSnapshot Contract 定稿：14 问可答、9 项纪律、evidence
             state 全量保存（非仅 confidence）（§17）。

核心保守性契约（§13.4）：False specificity is worse than incomplete
coverage。这是 V4 的 epistemic contract，不是 bug。

实施仍被 BLOCKED：14 项 Implementation Preconditions 未满足（§22）；
IMPLEMENTATION AUTHORIZATION = NOT GRANTED。

§2 V4 MISSION / NON-MISSION
================================================================================

2.1 Mission：
    M-1 把 V3 structural facts 映射为传统八字事件语义证据（Layer B）。
    M-2 在必要条件合取 + 排除信号 + ambiguity 纪律下形成 Event Family /
        Class candidates（Layer C）。
    M-3 输出可审计、可重解释、零 Double 的 EventSnapshot。
    M-4 为 AI Explanation Layer 提供枚举/序数输入。

2.2 Non-Mission（V4 永不声称）：
    N-1 不检测新的 structural interaction（检测权威 = V3）。
    N-2 不产生 V3 N1 / N2 / Domain / magnitude 语义。
    N-3 不回答「事件一定发生」；只回答「结构证据支持哪种事件语义候选、
        在什么时间分辨率上被观察」。
    N-4 不做 accuracy 声称；不做数值置信；不做医疗/法律专业判断。
    N-5 不替代用户对真实事件的确认；输出是语义候选不是事实陈述。

§3 STRUCTURAL FACT vs SEMANTIC EVIDENCE vs EVENT CANDIDATE
   (Hardening Rule #1 / H1)
================================================================================

3.1 Layer A — Structural Fact（V3 Structural Authority 独占）
    回答：「八字结构中机械发生了什么？」
    内容：interaction kind、participating pillars、Ten-God theme、slot
    attribution、N1 activation、direction、N2 magnitude、temporal
    evaluation、R-1~R-6 派生事实。全部词汇属于 V3 冻结词表。

3.2 Layer B — Semantic Evidence（V4 Event Semantics）
    回答：「某个 structural fact 是否具有某种传统事件语义？」
    内容：V4 rule registry 中显式登记的映射条目——每条把 V3 词汇组合
    （Layer A）标注为某 event family 的 supporting / conflicting /
    condition / exclusion / supplementary 证据。Layer B 不产生任何新结构
    事实；它只是「结构→语义」的登记表。

3.3 Layer C — Event Candidate（V4）
    回答：「综合必要条件后，是否可以形成某个 Event Family / Class
    candidate？」
    内容：candidate 状态机（no-candidate / dormant / supported /
    conflicted / unresolved / superseded）、specificity level、timing
    resolution、ambiguity class。

3.4 路径禁令与许可：
    FORBIDDEN path（永久禁止）：
      V4 raw Bazi → independently detect new structural interaction
      → directly create event
    理由：该路径绕过 V3 检测权威（P1）、绕过 Layer B 登记纪律、不可审计、
      是隐藏的第二 structural engine。

    ALLOWED path（唯一许可的 V4 自有派生路径）：
      raw Bazi → V4-owned supplementary semantic derivation → Event Evidence
      前提（全部满足，缺一即 FORBIDDEN）：
        (a) 不产生 V3 InteractionKind
        (b) 不产生 V3 N1 / V3 N2
        (c) 不产生新的 Domain
        (d) 不修改 V3 任何输出
        (e) 不构成隐藏的第二套 structural engine（见 3.5 Second-Engine
            Test）
        (f) 派生函数本身在 registry 中登记（derivation spec + version +
            literature provenance），产出只能是 Event Evidence 对象
            （§8 词表），不能是 V3 词表对象。

3.5 Second-Engine Test（H6 的可审计形式）：
    V4 supplementary derivation 合规当且仅当：
      T1 输出类型 ∈ Event Evidence 词表（§8），∉ {InteractionKind, N1,
         N2, Domain, magnitude, tier}；
      T2 派生是对既有 V3 kind/theme 的语义细化或对本命盘静态属性的标注
         （如藏干透出细化、性别六亲映射），不是新的柱位作用分类器——
         即不存在一个「V3 没有而 V4 新发明的两柱/三柱关系判定」；
      T3 V3 输出在 V4 开启前后逐字节不变（diff = empty）；
      T4 每条派生证据的 provenance 标注 origin = v4-supplementary +
         derivation ID + version。
    任一 T 不满足 → 判定 SECOND-ENGINE VIOLATION，该派生禁止进入 registry。

         合并发生在 L1 命名层（语义宽家族），分支区分发生在 L2（branch

    "Career / Work"），无泄漏。

    P-4 Master Matrix 中所有 class 已按 P-1~P-3 复审（§18，9 问审计）。

§9 TEMPORAL EVIDENCE CONTRACT (Hardening Rule #8 / H2/H8)
================================================================================

9.1 三层角色（冻结）：
      Year  = broad evidence（年度结构激活、方向、大运层输入、R-2/R-3/R-4）
      Month = timing-window evidence（12×month evaluations、R-1 windows、
              R-6 peakMonths——R-6 按 §16.4 provenance 契约消费）
      Day   = narrow corroboration；exact-date evidence 仅当该 class 的
              ExactDateDiscriminator ≠ NONE（§10）

9.2 Backflow 禁令（全部永久）：
      B-1 禁止 Day → Month → Year backflow（下层证据不得创造/修改上层
          结构事实）
      B-2 禁止 Month → Day identity inference（月窗口不得推断「事件发生
          在某个具体日」）
      B-3 禁止 Year → exact date inference（年层证据永不产生具体日期）
      补充：月→年、日→月的任何「证据回流」同样禁止；层间只有 §10.4 的
      冲突记录关系，没有覆盖关系。

9.3 Temporal Resolver 的唯一问题域：
      只回答：「evidence is observed at what temporal resolution?」
      不回答：「事件一定发生在哪一天」（N-3）。Resolver 输出是证据观察
      分辨率，不是事件发生时刻的承诺。

9.4 Timing Resolution 重定义（必要条件，全列）：
      YEAR_ONLY
        必要条件：(a) 年层 family/direction 证据存在；
                  (b) 月层无收敛窗口（无 R-1/R-6 月份收敛），或月层证据
                      缺席，或月层冲突未决；
                  (c) 未声称任何日层参与。
      MONTH_ONLY
        必要条件：(a) 年层或月层 family 证据存在；
                  (b) 月窗口收敛（R-1 window / R-6 peak month / 单月
                      收敛）；
                  (c) §10 EXACT_DATE 四条件未全部满足（保守回落）。
      EXACT_DATE
        必要条件（四条合取，缺一回落 MONTH_ONLY）：
                  (a) 月窗口收敛至单月；
                  (b) 日层同 family 同向结构 corroboration 存在；
                  (c) 该 class 的 ExactDateDiscriminator 在 ontology 中
                      登记为必要条件且非 NONE；
                  (d) 该 class RequiredConditionSet 全部满足。
      UNRESOLVED
        必要条件：层间方向冲突未决（双分支保留，§12）。
      附加不变量：日层 quiet ⇏ 事件不存在（三层独立评估，v1 §9.4 结论
      保留）；timing resolution 变更不改变候选身份（timing ≠ identity）。

9.5 与 v1 §9.4 的关系：本节整体取代 v1 §9.4（其 EXACT_DATE 定义见 §10.2
    废除记录）。

§10 EXACT-DATE SAFETY CONTRACT (Hardening Rule #2 / H2)
================================================================================

10.1 概念分离（冻结）：
       Timing Evidence        =「证据在什么时间分辨率上被观察到」
       Event Identity Evidence=「候选为什么是这个 family/class」
       二者独立：timing 证据永不参与身份判别；身份证据（含 day 层
       corroboration）永不单独产生 EXACT_DATE。

10.2 v1 §9.4 废除记录（before → after）：
       BEFORE（v1 §9.4，已废除）：
         EXACT_DATE ⟺ 月窗口收敛至单月 ∧ 日层同 family 同向族证据存在
         MONTH_ONLY ⟺ 月窗口存在 ∧ 日层无 corroboration 或矛盾未决
       废除理由：把「日层有同族结构」当作 exact-date 判据，等价于
         Day structural evidence → EXACT_DATE shortcut（任务书 Q3 所指）。
         任何月份中都存在结构日，该定义在几乎任何 marriage-family 月窗口
         内都会产出 EXACT_DATE，制造系统性 false specificity。
       AFTER（本契约）：
         Day-level same-family structural evidence is corroboration only.
         它不能单独把 MONTH_ONLY 升级为 EXACT_DATE。EXACT_DATE = §9.4
         四条件合取；理论不能可靠提供 discriminator 的 class 保守输出
         MONTH_ONLY。

10.3 Discriminator Registry（本轮状态）：
       本版 registry 对全部 Event Class 登记 ExactDateDiscriminator =
       NONE。理由：本轮没有为任何 class 找到并授权「为什么是这一天而非
       同月其他日」的可靠结构判据；择日体系（wedding）属 school plugin
       证据，按 §15 不得充当 structural discriminator。
       ⇒ 推论：**在本版 frozen contract 下 EXACT_DATE 不可达（reserved
       state）**。任何实现产出 EXACT_DATE 即为 contract violation。
       未来登记 discriminator 的程序：独立授权 + 文献 provenance +
       registry 版本递增 + holdout 重跑；禁止从历史案例倒推 discriminator。

10.4 层间分歧：年 broad + 月 narrow + 日 quiet（或其他组合）分歧按 §12
    冲突账本记录为 dual-branch/unresolved，不互相覆盖、不互相拉平。

§11 EVIDENCE STATE MODEL (Hardening Rule #4 / H4)
================================================================================

11.1 废除记录（before → after）：
      BEFORE（v1 §7[5] / §13）：单一 ConfidenceOrdinal =
        insufficient / single-signal / corroborated / broad / conflicted
        （沿用 N1 CONF-2 词表形态，事件域重定义）
      废除理由：该词表把「证据是否成立」（status）、「证据覆盖广度」
        （breadth）、「证据来源多重性」（corroboration）三个正交维度压进
        一条伪序数链；「corroborated > broad」这类排序无语义意义。
      AFTER：三字段正交模型。

11.2 三字段定义（candidate 级，core 与 plugin 各自独立计算，§15）：
      EvidenceStatus（证据是否成立）：
        insufficient  必要条件集未满足（候选 dormant）
        supported     必要条件集满足且无未决冲突
        conflicted    存在冲突且 registry 排除/否定规则已确定性裁决
                      （分支已降级/转移，§12.2）
        unresolved    存在冲突且无规则裁决（双分支保留）
      EvidenceBreadth（证据覆盖广度——候选证据跨越的独立 V3 观察面）：
        narrow    单一 domain ∧ 单一 temporal layer
        moderate  上述两维恰好一维多重
        broad     多 domain ∧ 多 temporal layer
        （「domain 计数」= 候选证据涉及的不同 V3 FortuneDomain 去重数；
          「layer 计数」= year/month/day 观察层去重数。仅此两处集合基数
          判定被允许，见 11.4。）
      Corroboration（来源多重性）：
        single-source   证据来自单一 V3 evaluation（如仅年层）
        multi-source    ≥2 个独立 V3 evaluation（如年+月）
        multi-temporal  同 family 证据跨 ≥2 temporal layer 且方向一致
      约束：三字段全部枚举；零 Double；无数值 confidence；三字段组合是
      tuple 不是 ladder——禁止定义任何跨 tuple 的全序。

11.3 与 v1 词表的迁移映射（仅用于解释，非运行期转换）：
      insufficient → status=insufficient（breadth/corroboration 照实记录）
      single-signal → {supported, narrow, single-source}
      corroborated  → {supported, narrow|moderate, multi-source}
      broad         → {supported, broad, multi-source|multi-temporal}
      conflicted    → {conflicted|unresolved, breadth 照实, corroboration
                       照实}（conflicted vs unresolved 由 §12.2 裁决）

11.4 聚合确定性：breadth/corroboration 的映射只允许「证据来源集合的基数
    → 枚举」（1→narrow、2→moderate、≥3→broad；层数 1/≥2 同理）。这是
    唯一被许可的数值使用（集合基数），不是评分；任何对证据「强度」的
    加权、求和、平均、归一化仍然禁止。

11.5 第四字段裁定：不设第四字段。候选存在性（no-candidate/dormant/
    present）与分支冲突记录已由候选级状态 + §12 账本承载，无需再引入
    一个混合维度字段。若未来需要，必须独立定义语义并走 registry 授权，
    不得复活单一 ordinal。

§12 CONFLICT / UNCERTAINTY MODEL
================================================================================

12.1 四态证据账本（继承 v1 §10.1，逐候选逐证据维护，永不平均）：
      supporting   支持 {green}
      conflicting  同 family 对立语义证据 {red}
      condition    前提性证据（满足 RequiredConditionSet 用）{gray}
      exclusion    排除信号 {yellow}
      （每条证据的 polarity 相对某 Event Family 定义；exclusion 是独立
       类型不是 polarity。）

12.2 冲突裁决规则（新增，保证 EvidenceStatus 确定性）：
      - conflicting evidence ≠ algorithm failure：冲突是八字语义常态，
        V4 显式呈现而非消解。
      - 同 family 对立分支并行保留（如 marriage-branch /
        disruption-branch），各自独立计证据，输出标注 branch conflict。
      - EvidenceStatus=conflicted ⟺ 某条 ExclusionSignal 规则被确定性
        触发（分支按规则降级/转移，全程留痕）。
      - EvidenceStatus=unresolved ⟺ 冲突存在但无 registry 规则裁决。
      - 禁止按证据「数量/强度」裁决冲突（无数值支配）；裁决只能来自
        registry 规则的显式枚举条件。
      - AGG-3 约束：多 family 证据先逐域聚合，候选层仅做序数级联合，
        不产生跨域数值。

12.3 输出状态词表（候选级，继承 v1 §10.3）：
      no-candidate / dormant-candidate / candidate-supported /
      candidate-conflicted / candidate-unresolved /
      candidate-superseded（lattice/排除规则裁决）。

12.4 合法负输出（任务书 Q9 正面回答）：no-candidate / dormant /
    insufficient / unresolved 是 V4 的一等公民输出，不是错误状态。证据
    不足时 V4 必须输出上述状态之一，禁止强行产出事件候选（§13.4）。

§13 SPECIFICITY LADDER (H3/H7 配套)
================================================================================

13.1 阶梯（继承 v1 §11，词表对齐 §4）：
      L0  Structural activation（V3 域状态——不是事件）
      L1  Broad Event Family candidate（仅 §4.1 词表；由 V3 域激活 +
          Layer B 登记直接生成，永远允许）
      L2  Specific Event Class candidate（需 ontology RequiredConditionSet
          合取 + family-specific discriminators）
      L3  Specificity refinement（如 registration vs ceremony）
          ——需 condition set（含 V4 supplementary / school module 证据）
          ——C 类禁入（§14）
          ——school module 证据可支持的 L3 须显式标注 SCHOOL-DEPENDENT，
            core 单独不可达（§15）

13.2 升级规则：逐级合取，缺任一必要前提 → 停级（dormant）。
     AmbiguityClass=C 的候选永不进入 L3。

13.3 方向性案例（任务书原文，hardened 答案）：
      - relationship structural activation ⟶ 只生成 L1 Relationship
        family candidate；marriage-formation（L2）需 §5.2 判据集；
        结构激活永远不直接等于 marriage。wedding-ceremony（L3）core
        不可达（§18 行 W-3）。
      - wealth activation ⟶ L1 Finance / Asset family candidate；其下
        走 B-3a（资产语义）或 B-3b（现金流语义）分支判据；property-
        acquisition（L2）需 §5.4 三分语义合取；否则停留 family 级。

13.4 V4 CORE 保守性契约（Hardening Rule #13，epistemic contract）：
      False specificity is worse than incomplete coverage.
      只能证明 Relationship family → 不输出 Marriage。
      只能证明 Children family → 不输出 Childbirth。
      只能证明 Finance/Asset family → 不输出 Property acquisition。
      只能证明 Movement family → 不输出 Immigration。
      只能证明 Health/Safety family → 不输出 Surgery。
      保守停级不是 bug，是 V4 的核心认识论承诺；任何为「覆盖率好看」而
      放宽判据的变更都违反本契约。

§14 AMBIGUITY CONTRACT (Hardening Rule #6 / H7)

14.1 HARD CEILING（冻结）：AmbiguityClass C 的候选永远停留在 L1/L2 +

       C + L3 = INVALID
     本轮登记的 C 类典型（不可唯一判别对）：

       financing vs generic financial movement
       surgery vs generic health negative event（surgery 因此整体

       immigration vs broader relocation

       wedding-ceremony 的具体日期（择日属流派，非结构判别）

    = L2 +（如适用）候选拆分展示对立语义分支。禁止输出任何唯一性声称。

14.3 未来 discriminator 的授权程序：新增独立且经授权的 discriminator

§15 SCHOOL PLUGIN AUTHORITY (Hardening Rule #5 / H5)

      Supplementary Evidence §8 桶 1，origin = v4-supplementary，计入

      School Plugin Evidence §8 桶 4，origin = school-plugin，只计入

15.2 Plugin 八项禁令（全部永久）：

      X-2 不得产生独立 Event Candidate（不得无中生有）

      X-8 不得静默改变 Event Class / Specificity

15.3 Plugin 抬升的显式登记：

        coreEvidenceState.status = insufficient（原样保留）
        pluginEvidenceState.contribution = lifted-insufficient-to-supported
      绝不能呈现为「Core independently detected event」。

15.4 coreEvidenceState / pluginEvidenceState 结构（审计对象）：

                             v4-supplementary origin）
      pluginEvidenceState  = {modules: [{moduleID, moduleVersion,
                             addedEvidenceRefs, contribution:
                             none / corroboration-added /
                             lifted-insufficient-to-supported / ...}],
                             aggregateNote}
      两态永不合并成一个数值或一个 ordinal。

15.5 存在性问题（Snapshot 必答）：
      「这个候选如果关闭所有 school plugins，还会不会存在？」
      答 = coreEvidenceState.status ∈ {supported, conflicted, unresolved}
      （即 core 独立成立）。字段 derivedPluginIndependence: Bool 由
      coreEvidenceState 机械派生，供 UI/AI 直接引用。

15.6 Interim 治理（OQ-4 未决期间的强制规则）：
      - 所有 plugin 默认关闭；启用需显式配置 + 版本登记。
      - EventSnapshot 携带 pluginManifest（启用模块 + 版本）。
      - 无 manifest 的 snapshot 视为 plugin 全关（derivedPluginIndependence
        = true）。
      - 正式授权/审计流程 → OQ-4 DEFERRED（§21）。

§16 V3 ↔ V4 AUTHORITY BOUNDARY (H10)
================================================================================

16.1 权属（继承 v1 §12）：
      V3 owns（冻结）：structural detection / interaction semantics /
        magnitude (N2) / domain attribution / temporal evaluation /
        snapshot derivation (R-1~R-6)。
      V4 owns：event ontology / candidate generation / event evidence
        aggregation / specificity / timing interpretation（§9 界定）/
        evidence state。
      方向唯一：V4 → V3 只读；无任何反馈路径。

16.2 只读接口（继承 v1 I-1~I-3）：
      I-1 V3EvaluationResult（year / 12×month / day 三视图）
      I-2 YearV3Snapshot（12×month cache、R-1~R-4、R-6、quietDomains、
          overflowDomains）
      I-3 V3EventRecord / familyID（经 audit trail）

16.3 证据可追溯性（H10 正面回答）：每条 Event Evidence 必须携带：
      origin ∈ {v3-core, v4-supplementary, school-plugin}
      provenance 链：
        v3-core          → sourceEvaluation（年/月#k/日）→
                           sourceInteraction（V3EventRecord/familyID）→
                           V3 原始输出
        v4-supplementary → derivationID + version → 派生输入（原始四柱
                           / V3 引用）
        school-plugin    → moduleID + moduleVersion → 模块内部输入声明
      + rule provenance（registry 规则 ID + 版本 + 文献出处）。
      「为什么产生此候选」= RequiredConditionSet 所引用的证据清单 +
      排除信号缺席事实，全部可沿上述链回放。

16.4 R-6 消费契约（OQ-2 落地，Hardening Rule #9）：
      裁定：YES — V4 may consume R-6 data already preserved in
      YearV3Snapshot（presentation-hidden ≠ semantic-unavailable）。
      约束（全部强制）：

    semantics、provenance = YearV3Snapshot.R6 而非 evaluate(.year)）。

  OQ-3（AmbiguityClass C 是否允许 L3）
    DISPOSITION: CLOSED / NO。
    C + L3 = INVALID（§14）。未来新 discriminator 须独立授权 + 文献
    provenance，禁止历史案例倒推。

  OQ-4（School plugin 授权/启用/审计治理）
    DISPOSITION: DEFERRED（治理流程未完整定义）。
    Interim 强制规则（§15.6）：plugin 默认关闭 + pluginManifest 强制
    披露 + 八项禁令（§15.2）+ 存在性问题可答（§15.5）。正式授权流程
    （谁批准、审计周期、违规处置）留待独立治理设计。

    DISPOSITION: DEFERRED（presentation phase）。
    原因：属 V4 UI/呈现阶段议题；本轮 §17 已保证 Snapshot 自足（14 问
